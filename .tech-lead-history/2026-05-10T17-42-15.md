- Что нарушено: в `README.md` зафиксирована стратегия — публиковать React-компоненты как custom elements через `@r2wc/react-to-web-component`. - Как исправить: добавить `src/web-components/index.ts` с регистрацией `xopa-button`, `xopa-input`, `xopa-input-password`, `xopa-typography`, `xopa-eye-toggle`; настроить `vite.config.ts` на library mode со вторым entry; обновить `package.json` (`exports`, `main`/`module`, `files`, build-скрипт).
- Специалист: frontend
- Сложность: medium
- Срочность: высокая

**Анализ:**
Стратегия принята, но не реализована — это блокирует всех Vue-консьюмеров и делает зависимость `@r2wc/react-to-web-component` мёртвой. Нужен entry, который импортирует существующие React-компоненты из `src/shared/ui/*`, оборачивает их `r2wc(...)` и регистрирует через `customElements.define`. Параллельно — `vite.config.ts` в library mode (`build.lib` с двумя entry: основной React-экспорт и `web-components`), `external: ['react','react-dom']`, формат `es`. Не трогать SPA-демо (`src/App.tsx`, `src/main.tsx`) и базовый путь `/ui-kit-animations/` для Storybook/gh-pages — только добавить второй сценарий сборки. Маппинг пропс→атрибут (особенно `disabled`, `loading`, `variant`, `size`) должен обрабатывать булевы атрибуты корректно — это типичный источник багов в r2wc.

**План:**

2. Дополнить `vite.config.ts` секцией `build.lib` с двумя entry (`index` + `web-components`), `rollupOptions.external` для `react`/`react-dom`, форматами `es`.
3. В `package.json` добавить `exports` (поля `.` и `./web-components`), `main`, `module`, `types`, `files`; добавить скрипт `build:lib`.
4. Прогнать сборку, проверить, что `dist/web-components/index.js` загружается standalone (минимальный smoke-html в `public/` или ручная проверка через `vite preview`).
